# Domain docs

Onyx uses one root `GLOSSARY.md` and keeps architecture decision records
(ADRs) under `docs/adr/`.

Before exploring the codebase, read the glossary and any ADRs relevant to
the task. If these paths are absent, continue. The `domain-modeling` skill
creates them as terms and decisions are settled.

Use glossary terms in issues, proposals, and tests. Reconsider unfamiliar
terms and record genuine vocabulary gaps for `domain-modeling`. If a proposal
conflicts with an ADR, cite the ADR and explain why it may need to be reopened.
